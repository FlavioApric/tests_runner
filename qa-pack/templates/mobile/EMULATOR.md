# Android emulator recipe ({{PROJECT}})

Generated by `qa-pack/scripts/plans.mjs` from qa.config.json `mobile`. The Maestro series needs a booted emulator
with the app installed and the local backend reachable from the device.

## One-time setup

1. Android SDK command-line tools, platform-tools and the emulator package (`sdkmanager`).
2. System image: `sdkmanager "system-images;android-{{API_LEVEL}};{{TARGET}};x86_64"`.
3. AVD: `avdmanager create avd -n {{AVD}} -k "system-images;android-{{API_LEVEL}};{{TARGET}};x86_64" -d {{PROFILE}}`.
4. Maestro CLI {{MAESTRO_VERSION}}: download `maestro.zip` from the Maestro releases and check its sha256
   (`{{MAESTRO_SHA256}}`) before unzipping. Set `MAESTRO_BIN` if it is not on PATH.

## Every series

1. Start the local stack: `{{STACK_UP}}`.
2. Boot: `emulator -avd {{AVD}} -no-snapshot -no-boot-anim -gpu swiftshader_indirect` and wait for
   `adb shell getprop sys.boot_completed` to print `1`.
3. Ports the app calls on the host: `adb reverse tcp:<port> tcp:<port>` for each of: {{REVERSE_PORTS}}.
4. Build and install: `{{BUILD}}`, then `adb install -r {{APK}}` (app id `{{APP_ID}}`).
5. Run: `node {{PACK}}/scripts/maestro-run.mjs --runs {{RUNS}} --fresh` (or `--resume` on the same artifact).
6. Evidence: `{{OUT}}/REPORT.md`, `state.json`, `junit/`, `failures/`. Copy the result into
   the G5 evidence file `maestro-series.md` and sign it.

## Rules

- The series passes only with {{RUNS}} green runs in a row on the SAME artifact (APK + flows fingerprint).
- A flow/app failure resets the streak; an infra-hang is an incident and stays in the record; only runs where the
  device was not ready before any flow ran are voided and redone.
- Nothing is retried to turn a failure green.

## In CI

`qa-pack/templates/github/maestro-android.yml` is the GitHub Actions template (android-emulator-runner, pinned by
SHA). The rendered version for this project is in `{{PLANS}}/maestro-android.yml`. Copy it to `.github/workflows/`
only with the owner's approval.
