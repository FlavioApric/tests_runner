# fix.config.json

One JSON file at the repo root holds every project value the fix scripts use. The scripts find it at `<repo root>/fix.config.json`; `$FIX_CONFIG` or `--config <path>` points elsewhere. All patterns are JavaScript regular expressions written as JSON strings (so `\.` is `"\\."`), matched against repo-relative paths with forward slashes. Missing keys take the defaults in `scripts/fix/lib.mjs` (`DEFAULTS`). A bad regex or an unknown type stops the script with the key that is wrong.

The [`../fix.config.json`](../fix.config.json) on this branch is a working example for a web app with server functions, SQL migrations and a native shell; [`examples/supabase-capacitor.json`](examples/supabase-capacitor.json) is a fuller one for a monorepo with the app in `app/` and the backend in `supabase/`.

## Repository and branches
| Key | Example | Meaning |
|---|---|---|
| `baseBranch` | `"main"` | fixes are cut from `<remote>/<baseBranch>`, and the gate diffs against it |
| `remote` | `"origin"` | the remote that holds the base branch |
| `repo` | `"your-org/your-app"` | the GitHub repo of the fix PRs, used by `ship.mjs <PR>` (override with `--repo`) |
| `runnerRepo` | `"your-org/your-runner"` | where the runner workflows live; used in `ownerActions` and `readOnlyChecks` as `{runnerRepo}` |
| `branchPrefix` | `"fix/"` | the branch is `<branchPrefix><id>-<slug>`; `ship.mjs` checks the name |
| `worktreePrefix` | `"wt-"` | the worktree folder, beside the repo: `<worktreePrefix><id>-<slug>` (lowercase) |

## Cards and records
| Key | Example | Meaning |
|---|---|---|
| `cardDir` | `"fix/bugs"` | one card per bug, `<cardDir>/<id>.md` |
| `cardTemplate` | `"fix/templates/BUG.md"` | read from the checkout you run `start.mjs` in; placeholders `{{ID}}`, `{{SLUG}}`, `{{TITLE}}`, `{{DATE}}`, `{{BRANCH}}`, `{{TESTS_BRANCH}}` |
| `logFiles` | `["fix/LOG.md"]` | `ship.mjs` wants a row in at least one of these; `[]` turns the check off |
| `idPattern` | `"^BUG-[A-Za-z0-9_-]{1,36}$"` | a valid bug id |
| `idExample` | `"BUG-F20260101-1"` | shown in error messages |
| `slugPattern` | `"^[a-z0-9-]{2,40}$"` | a valid slug |
| `briefDir` | `".fix-batch"` | where `fix-batch.mjs` writes briefs and the plan (`<briefDir>/<batch>/`); keep it out of git |

## Delivery types
| Key | Example | Meaning |
|---|---|---|
| `deliveryOrder` | `["none","web","function","migration","native"]` | the types, lowest first; must start with `"none"` (tests, docs, scripts). The highest type among the changed files is the delivery |
| `deliveryRules` | `[{"type":"native","path":"^(android\|ios)/"}, ...]` | path regex to type; **the first rule that matches a file wins**, so put narrow rules first. A file that no rule matches is `none` |
| `blockingTypes` | `["native"]` | types the fast path cannot carry: `gate.mjs` exits 1 and `ship.mjs` fails |
| `nativeDeps` | `{"manifest":"package.json","pattern":"^@capacitor/","type":"native"}` | when `manifest` changed, compare its dependencies matching `pattern` with the base; any difference adds `type` (default: the last type in `deliveryOrder`). `null` turns it off |
| `ownerActions` | `{"web":"Owner: approve \"deploy-web\" with pr={pr}", ...}` | the text `gate.mjs` and `ship.mjs` print for the top type; placeholders `{pr}`, `{branch}`, `{repo}`, `{runnerRepo}` (an unknown value prints as `<pr>`). A `default` key covers types without their own entry |
| `readOnlyChecks` | `["gh workflow run verify.yml --repo {runnerRepo} -f repo={repo} -f ref={branch}"]` | commands that only read, which Claude may start; printed by `ship.mjs <PR>` |

## Checks
`checks` is the path to command map the gate runs:

```json
{ "name": "build", "cmd": "npm run build", "cwd": "app", "paths": ["^app/src/"], "kinds": [], "full": true, "stack": false }
```

| Field | Meaning |
|---|---|
| `name`, `cmd` | required; `cmd` runs in a shell |
| `cwd` | relative to the repo root, default `"."` |
| `paths` | regexes; the check runs when any changed file matches one |
| `kinds` | delivery types; the check also runs when the change has one of them |
| `full` | default `true`: part of `gate.mjs --full`. `false` keeps a slow check out of `--full` |
| `stack` | default `false`. `true`: needs a local stack, runs only with `--stack` or `--full` |

## Tests and results
| Key | Example | Meaning |
|---|---|---|
| `testPaths` | `["^tests/", "\\.(test\|spec)\\.[cm]?[jt]sx?$"]` | a change with a delivery type must touch one of these (the regression test) |
| `resultFiles` | `["^test-results/", "^playwright-report/"]` | files that must never be in a fix PR (generated by runs) |
| `requirementIdPattern` | `"R\\d+-\\d+"` | a requirement id; `ship.mjs <PR>` wants one in the PR text. `""` turns that part off |
| `testsBranch` | `"test-plan"` | the branch that holds the test plan; the PR text must name it. `""` turns the ticket check off |
| `featureChecks` | `[{"label":"decision recorded","path":"^docs/DECISIONS\\.md$"}]` | `ship.mjs --feature`: each label needs a changed file matching its path |

## Trying the rules
```
node scripts/fix/gate.mjs --files src/a.ts,functions/x/index.ts,android/app/build.gradle --list
node scripts/fix/gate.mjs --files db/migrations/0042_add.sql --json --stack
```
`--json` prints the type of every file (`perFile`), so a rule that does not match shows at once.
